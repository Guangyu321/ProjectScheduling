# 模拟配置样例

- `workcell.json`：10 台模拟设备、独立物理槽位、处理/装载口资源、共享运动区域及机器人可达位置。
- `workflow.json`：2 块板，每板 6 次搬运和 6 个处理步骤，共 24 步；已经展开，不含模板变量。

当前示例路径：堆栈 → 扫码 → 移液 → 封膜 → 振荡 → 检测 → 冰箱。撕膜机和离心机在设备目录中登记，但不参与这条示例流程。所有方法 ID、板型 SIM_96 和时间值都只用于模拟，检测值 100 SIM_AU 没有生物学意义。

模拟器不执行真实驱动，不打开 TCP、串口或厂商 SDK。工作流必须显式设置 `simulation_only: true`。

运行：在 `backend/` 目录执行 `python -m lab_orchestrator.demo`，或使用 README 中的 `run_demo` 函数。输出包含控制器数据库、独立设备账本、JSON 记录和实际执行甘特图。

第一版限制：每个数据库一个批次；每块板为有序线性依赖链；固定设备和目的板位；资源容量均为 1。分支/汇合、工艺时间窗、真实库存和设备参数模式校验按后续阶段实施。

搬运所需资源由校验模块统一推导：机械臂处理通道、夹爪、共享区域、源/目标设备处理通道与装载口、源/目标位置和当前板。全部资源一次取得；物理位置在完成证据确认前保留最后已知记录并标为 unknown。

配置里预留的缓冲位不意味着已经实现绕行规划。无法取得目标位置且没有在途动作时，当前内核返回 blocked 并记录原因；自动缓冲绕行属于后续阶段。
